      Sistema de diseño Base de Uber

      Todos los componentes, botones, variantes, tamaños, inputs y tokens que utilizan los agentes provienen estrictamente del Base Design System (base.uber.com). A continuación puedes ver y probar visualmente cada componente.

      1. Sistema de botones (Uber Base Buttons)

      Jerarquía oficial según la especificación de Base Web y Mobile (baseui/button). Con alto contraste (#000000 / #FFFFFF), tipografía Uber Move Text Bold y variantes de forma (Píldora, Redondeado 8px, Cuadrado y Círculo).

      Documentación oficial de botones ↗

      1.1 Variantes de jerarquía (Kinds)

      KIND: primary · secondary · tertiary · minimal · negative · positive
      Primary (KIND.primary · #000000)
      Secondary (KIND.secondary · #EEEEEE)
      Tertiary / Outline (KIND.tertiary)
      Minimal / Ghost (KIND.minimal)
      Negative / Destructive (#E11900)
      Positive / Success (#0E8345)

      1.2 Formas geométricas (Shapes)

      SHAPE: pill · rounded · square · circle
      SHAPE.pill · 9999px (Firma móvil Uber)
      SHAPE.rounded · 8px (Estándar Base Web)
      SHAPE.square · 0px (Estilo sharp)
      SHAPE.circle · Icon Buttons

      1.3 Escala de tamaños (Sizes)

      SIZE: large (56px) · default (48px) · compact (36px) · mini (28px)
      SIZE.large · 56 px (Hero / Sticky CTA)
      SIZE.default · 48 px (Estándar táctil)
      SIZE.compact · 36 px (Secundario / Filtros)
      SIZE.mini · 28 px (Inline / Tablas)

      Piezas técnicas

      Modelo y agentes

      • Claude vía API, con el Agent SDK para los agentes que usan herramientas.
      • Cada agente tiene instrucciones propias y un formato de salida fijo (JSON), así el siguiente lo puede leer.
      • Tokens y guías de Uber Base DS como contexto compartido inmutable.

      Integraciones

      • Jira y Trello: webhooks de entrada y API para comentar y mover tarjetas.
      • Repositorio de Uber Base DS (tokens W3C y componentes).
      • Figma: lectura de la librería Base y creación de la página v0.
      • Analítica de conversión y telemetría.

      Control y seguridad

      • Los agentes nunca publican en producción ni aprueban sin supervisión.
      • Permisos mínimos: solo los proyectos y tableros de diseño.
      • Registro de cada ejecución para auditoría.
      • Datos de clientes y pasajeros fuera del alcance de los modelos.

      Plan de adopción

      Semanas 1–2

      Preparar la base

      Documentar Uber Base DS en código (tokens y componentes), conectar un tablero de pruebas y configurar los agentes de brief y contexto.

      Semanas 3–6

      Piloto con un equipo

      Activar la cadena completa en un flujo real de movilidad o recarga. Medir tiempo hasta el primer borrador y tasa de reutilización de componentes.

      Semana 7 en adelante

      Escalado

      Ajustar instrucciones con el feedback del equipo de diseño de producto y extender a más servicios del ecosistema.

      Los tiempos y métricas de esta demo ilustran el flujo productivo agéntico bajo el sistema de diseño oficial de Uber.
